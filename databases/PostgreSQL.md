# PostgreSQL — шпаргалка по SQL для новичка

## 1. Что это и зачем

PostgreSQL — реляционная СУБД с транзакциями, расширениями и типом `jsonb`. Подходит для веб-приложений и отчётности. Для простого локального приложения без отдельного сервера часто достаточно SQLite. Примеры рассчитаны на PostgreSQL 18 и используют синтаксис, доступный и в ряде предыдущих версий. Текущий стабильный выпуск сверяйте на [странице загрузок](https://www.postgresql.org/download/).

## 2. Установка

`psql` — клиент. Для локальной практики установите также сервер. Для всех платформ есть альтернатива в виде [официального образа Docker](https://hub.docker.com/_/postgres). Для версии 18 используйте тег `postgres:18` и следуйте инструкции образа по хранению данных.

### Windows 10/11 — PowerShell

Используйте установщик EDB со [страницы PostgreSQL для Windows](https://www.postgresql.org/download/windows/). Выберите сервер и Command Line Tools, запомните порт и пароль администратора. Если `psql` недоступен, добавьте каталог `bin` установленной версии в пользовательский `Path` и откройте новый терминал.

```powershell
psql --version
```

Для удаления воспользуйтесь разделом **Параметры → Приложения → Установленные приложения**. Каталог данных проверяйте отдельно.

### macOS — Intel и Apple Silicon

```bash
brew install postgresql@18
```

```bash
brew services start postgresql@18
```

```bash
"$(brew --prefix postgresql@18)/bin/psql" --version
```

Добавьте следующую строку в `~/.zshrc` для запуска `psql` без полного пути. Альтернатива Homebrew — Postgres.app, доступный по ссылке со [страницы PostgreSQL для macOS](https://www.postgresql.org/download/macosx/).

```bash
export PATH="$(brew --prefix postgresql@18)/bin:$PATH"
```

```bash
brew services stop postgresql@18
```

```bash
brew uninstall postgresql@18
```

### Ubuntu / Debian

```bash
sudo apt update
```

```bash
sudo apt install postgresql
```

```bash
psql --version
```

Для конкретной версии используйте официальный репозиторий PostgreSQL Apt по инструкции для [Ubuntu](https://www.postgresql.org/download/linux/ubuntu/) или [Debian](https://www.postgresql.org/download/linux/debian/). Системные пакеты предоставляют `psql` в стандартном `PATH`.

```bash
sudo apt remove postgresql
```

`postgresql` — метапакет. Если нужен полный демонтаж, отдельно проверьте установленные пакеты сервера и клиента с номером версии перед удалением.

### Arch Linux

```bash
sudo pacman -Syu postgresql
```

На новой установке с пустым каталогом данных инициализируйте кластер и запустите службу. Для существующего кластера эти команды инициализации пропустите.

```bash
sudo -iu postgres initdb --locale=C --encoding=UTF8 -D /var/lib/postgres/data
```

```bash
sudo systemctl enable --now postgresql.service
```

```bash
psql --version
```

Альтернатива — официальный образ Docker. Перед удалением нативного пакета остановите службу.

```bash
sudo systemctl disable --now postgresql.service
```

```bash
sudo pacman -R postgresql
```

Команды с `sudo` меняют системные настройки или пакеты. `pacman -Syu` обновляет и остальные пакеты. Перед удалением проверьте зависимости и сделайте резервную копию нужных баз.

## 3. Особенности по ОС

- **Windows.** Проверьте состояние службы PostgreSQL и порт из установщика. В WSL клиент и сервер внутри дистрибутива настраиваются как в Linux.
- **macOS.** Формулы Homebrew с номером версии могут не попасть в `PATH` автоматически. `brew --prefix` учитывает архитектуру.
- **Linux.** Локальный сокет может использовать `peer`, то есть сверять роль базы с именем пользователя ОС. Подключение по TCP через `-h localhost` соответствует отдельным правилам `pg_hba.conf`.
- **Все ОС.** Версию сервера показывает `SHOW server_version`. Команда `psql --version` показывает версию клиента.

## 4. Быстрый старт

Войдите в `psql` под администратором к базе `postgres`. На Windows типичная роль установщика — `postgres`. На Ubuntu/Debian или Arch можно открыть локальный сеанс командой для системного пользователя `postgres`. На macOS при установке через Homebrew начальная роль обычно совпадает с системным именем пользователя.

```powershell
psql -h localhost -U postgres -d postgres
```

```bash
sudo -iu postgres psql -d postgres
```

```bash
psql -d postgres
```

Выполните подходящую команду входа, затем один раз создайте учебную базу. Примеры работают под владельцем этой базы. Команда `\c` относится к `psql`.

```sql
CREATE DATABASE sql_practice;
```

```text
\c sql_practice
```

```sql
SELECT 'Hello, PostgreSQL!' AS message;

CREATE TABLE demo_orders (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    order_code varchar(20) NOT NULL UNIQUE,
    customer varchar(100) NOT NULL,
    total_cents numeric(12, 0) NOT NULL CHECK (total_cents >= 0),
    ordered_on date NOT NULL DEFAULT CURRENT_DATE
);

INSERT INTO demo_orders (order_code, customer, total_cents)
VALUES ('A101', 'Anna', 1500), ('A102', 'Ivan', 3000);

SELECT customer, total_cents FROM demo_orders ORDER BY id;
```

Последний запрос покажет Anna с `1500` и Ivan с `3000`.

## 5. Основной синтаксис

| Команда | Что делает | Пример |
|---|---|---|
| `SELECT` | Выбирает столбцы | `SELECT customer FROM demo_orders` |
| `WHERE` | Фильтрует строки | `WHERE total_cents >= 2000` |
| `ILIKE` | Ищет по шаблону без учёта регистра | `WHERE customer ILIKE 'an%'` |
| `IS NULL` | Проверяет отсутствие значения | `WHERE customer IS NULL` |
| `ORDER BY` | Сортирует | `ORDER BY total_cents DESC, id` |
| `LIMIT / OFFSET` | Ограничивает выдачу и пропускает строки | `LIMIT 5 OFFSET 5` |
| `JOIN` | Соединяет совпавшие строки | `JOIN demo_orders AS b ON b.customer = a.customer` |
| `LEFT JOIN` | Сохраняет строки слева без пары | `LEFT JOIN demo_orders AS b ON b.id = a.id + 1` |
| `GROUP BY` | Группирует строки | `GROUP BY customer` |
| `COUNT / SUM` | Считает строки и суммы | `COUNT(*), SUM(total_cents)` |
| `HAVING` | Фильтрует группы | `HAVING COUNT(*) > 1` |
| `WITH` | Даёт имя подзапросу | `WITH totals AS (SELECT SUM(total_cents) AS amount FROM demo_orders) SELECT amount FROM totals` |
| `ROW_NUMBER` | Нумерует строки внутри группы | `ROW_NUMBER() OVER (PARTITION BY customer ORDER BY id)` |
| `DISTINCT ON` | Выбирает первую строку каждой группы | `SELECT DISTINCT ON (customer) * FROM demo_orders ORDER BY customer, ordered_on DESC, id DESC` |
| `COALESCE` | Возвращает первое значение, отличное от `NULL` | `COALESCE(SUM(total_cents), 0)` |
| `::` | Выполняет приведение типа | `total_cents::text` |
| `-> / ->>` | Извлекает поле JSON как JSON или текст | `SELECT '{"customer":"Anna"}'::jsonb ->> 'customer'` |
| `INSERT` | Добавляет строки | `INSERT INTO demo_orders (order_code, customer, total_cents) VALUES ('A103', 'Anna', 2000)` |
| `UPDATE` | Изменяет строки | `UPDATE demo_orders SET total_cents = 2500 WHERE order_code = 'A101'` |
| `DELETE` | Удаляет строки | `DELETE FROM demo_orders WHERE order_code = 'A102'` |
| `ON CONFLICT` | Обрабатывает конфликт уникальности при вставке | `ON CONFLICT (order_code) DO NOTHING` |
| `RETURNING` | Возвращает строки, затронутые изменением | `RETURNING id, total_cents` |
| `CREATE INDEX` | Создаёт индекс | `CREATE INDEX demo_orders_customer_idx ON demo_orders (customer)` |
| `BEGIN / COMMIT / ROLLBACK` | Открывает, фиксирует или откатывает транзакцию | Полный пример ниже |

```sql
BEGIN;

INSERT INTO demo_orders (order_code, customer, total_cents)
VALUES ('A101', 'Anna', 2500)
ON CONFLICT (order_code) DO UPDATE
SET total_cents = EXCLUDED.total_cents
RETURNING order_code, total_cents;

ROLLBACK;

SELECT total_cents FROM demo_orders WHERE order_code = 'A101';
```

`RETURNING` покажет `2500`. Запрос после отката покажет `1500`. `UPDATE` и `DELETE` без `WHERE` затрагивают все строки. Перед изменением проверьте фильтр через `SELECT`.

## 6. Конфигурация

`postgresql.conf` задаёт параметры сервера. `pg_hba.conf` определяет правила доступа. На Ubuntu/Debian типичный путь к обоим файлам — `/etc/postgresql/<version>/<cluster>/`. На Arch при описанной установке — `/var/lib/postgres/data/`. На Windows и macOS пути зависят от установщика и кластера. Точные пути можно узнать в `psql` под администратором.

```sql
SHOW config_file;
SHOW hba_file;
```

Минимальный фрагмент `postgresql.conf` для локальных TCP-подключений. Чтобы применить эти параметры, потребуется перезапуск сервера. При работе только с запросами менять настройки установки обычно не нужно.

```ini
listen_addresses = 'localhost'
port = 5432
```

## 7. Полезные приёмы

- В `psql` команды `\dt`, `\d demo_orders`, `\conninfo` и `\q` показывают таблицы, структуру, текущее подключение и закрывают сеанс. Точка с запятой для них не требуется.
- Кавычки `'...'` обозначают строки. PostgreSQL приводит имена без двойных кавычек к нижнему регистру.
- Для стабильного `LIMIT` задайте `ORDER BY` с уникальным последним ключом, например `id`.
- Используйте параметры драйвера для пользовательского ввода. Нативные позиционные параметры PostgreSQL записываются как `$1`, `$2`.
- `EXPLAIN` показывает план. `EXPLAIN ANALYZE` действительно выполняет запрос, поэтому сначала экспериментируйте с `SELECT`.
- `timestamptz` подходит для моментов времени. При выводе значение отображается в часовом поясе сеанса.

## 8. Частые ошибки

| Ошибка | Причина | Решение |
|---|---|---|
| `connection refused` | Сервер не слушает указанный адрес или порт | Проверьте службу, хост и порт |
| `Peer authentication failed` | Роль не совпадает с системным пользователем | Используйте соответствующего пользователя ОС или TCP с настроенной парольной аутентификацией |
| `relation does not exist` | Открыта другая база, схема или указано неверное имя | Проверьте `\conninfo` и укажите схему таблицы |
| `duplicate key value violates unique constraint` | Уникальный ключ уже существует | Проверьте данные или задайте правило `ON CONFLICT` |
| `current transaction is aborted` | Предыдущая команда завершилась ошибкой в открытой транзакции | Выполните `ROLLBACK` и повторите исправленную транзакцию |
| `column must appear in the GROUP BY clause` | Столбец выбран вне группировки или агрегата | Добавьте столбец в `GROUP BY` или агрегируйте его |
