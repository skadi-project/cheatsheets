# Linux — очистка диска

Для Debian, Ubuntu и Arch Linux. Начните с заполненной файловой системы, найдите источник роста и повторите замер после очистки. На сервере учитывайте срок хранения журналов и резервных копий.

## 1. Найти, что занимает место

```bash
df -hT
```

```bash
df -i
```

```bash
sudo du -xhd1 /var | sort -h
```

```bash
sudo find /var -xdev -type f -size +500M -printf '%s\t%p\n' | sort -nr | head -n 20
```

Замените `/var` каталогом на заполненной файловой системе. `-x` у `du` и `-xdev` у `find` ограничивают обход одной файловой системой. Если `/var` смонтирован отдельно, проверяйте его отдельно от `/`. Поиск показывает размер в байтах, для разреженных файлов фактическое место может быть меньше.

Если `df` показывает занятое место, которого нет в `du`, проверьте удалённые файлы, которые ещё открыты процессами. Потребуется пакет `lsof`.

```bash
sudo lsof +L1
```

При таком сценарии место освободится после закрытия файла процессом. Определите службу и используйте поддерживаемый способ переоткрытия журнала или согласованный перезапуск.

## 2. Кэш и зависимости пакетов

### Debian / Ubuntu

Просмотрите кандидатов на удаление. При необходимости пометьте нужные пакеты как установленные вручную через `apt-mark manual`.

```bash
sudo apt-get -s autoremove
```

```bash
sudo apt autoremove
```

Очистите кэш скачанных архивов пакетов. Установленные программы сохранятся, а для переустановки может потребоваться повторная загрузка.

```bash
sudo apt clean
```

### Arch Linux

`paccache` входит в `pacman-contrib`. Следующие команды сначала показывают кандидатов, затем удаляют старые архивы, сохраняя до трёх версий каждого пакета в кэше.

```bash
paccache -d -k 3
```

```bash
sudo paccache -r -k 3
```

```bash
pacman -Qdt
```

Последняя команда показывает зависимости-сироты. Просмотрите список и удаляйте пакеты по именам через `sudo pacman -Rs`. Если есть сомнения, проверьте назначение пакета через `pacman -Qi`. Кэш может пригодиться для отката.

## 3. Журналы systemd

```bash
sudo journalctl --disk-usage
```

После проверки требований к хранению можно удалить архивные записи старше выбранного срока. Здесь `--rotate` сначала переводит активные журналы в архив, а `--vacuum-time` удаляет архивные файлы по возрасту.

```bash
sudo journalctl --rotate --vacuum-time=14d
```

Для постоянного ограничения размера задайте подходящие `SystemMaxUse` и `MaxRetentionSec` в файле `/etc/systemd/journald.conf.d/limits.conf`. Отдельные текстовые журналы в `/var/log` обслуживайте через logrotate. Его режим `-d` показывает действия без изменений.

```bash
sudo logrotate -d /etc/logrotate.conf
```

## 4. Временные и пользовательские файлы

- **`/tmp` и `/var/tmp`.** Проверьте правила в `/etc/tmpfiles.d` и `/usr/lib/tmpfiles.d`. На systemd очистку по возрасту обычно запускает `systemd-tmpfiles-clean.timer`. Ручное удаление активных временных файлов может нарушить работу приложений.
- **`~/.cache`.** Найдите крупный подкаталог, закройте соответствующее приложение и очистите только его документированный кэш. Для браузера удобнее встроенная настройка. Каталоги `~/.config` и `~/.local/share` могут содержать настройки и данные.
- **Корзина и загрузки.** Просмотрите корзину через файловый менеджер. В `~/Downloads` сначала проверьте крупные файлы, дубликаты и старые установщики.

```bash
du -h -d 1 -- "$HOME/.cache" | sort -h
```

```bash
find "$HOME/Downloads" -maxdepth 1 -type f -mtime +30 -print
```

## 5. Docker и системные данные

Если установлен Docker, сначала проверьте использование диска и список остановленных контейнеров.

```bash
docker system df -v
```

```bash
docker ps -a --filter status=exited
```

```bash
docker image prune
```

Последняя команда с подтверждением очищает образы без тега, которые не используются контейнерами. У проверенных остановленных контейнеров используйте удаление по имени. Перед удалением тома определите, какие данные в нём хранятся. Обслуживайте Docker через его CLI, включая ресурсы в `/var/lib/docker`.

Старые ядра удаляйте через пакетный менеджер. Сверьте текущее ядро по `uname -r` и сохраните рабочий запасной вариант, если он есть. Файлы в `/boot`, базы в `/var/lib` и содержимое `/usr` обслуживайте средствами пакета или приложения.

## 6. Проверить результат

| Симптом | Что проверить |
|---|---|
| Удаление файла не освободило место | Открытые файлы через `lsof +L1`, снапшоты и файловую систему назначения |
| Место есть, но новый файл не создаётся | `df -i` и квоту пользователя |
| `du` выдаёт `Permission denied` | Права доступа и необходимость `sudo` для диагностического чтения |
| Журнал после очистки всё ещё большой | Активные файлы журнала и ограничения journald |

```bash
df -hT
```

```bash
df -i
```
