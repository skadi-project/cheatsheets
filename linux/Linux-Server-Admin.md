# Администрирование серверов Linux

Для Debian, Ubuntu и Arch Linux с systemd. Примеры используют Bash. `admin@server.example.com` и `nginx.service` замените своими значениями. Стандартные утилиты поставляются с дистрибутивом, `ss` и `ip` входят в iproute2.

## 1. Первичная диагностика

| Команда | Что смотреть |
|---|---|
| `hostnamectl` | Имя хоста, дистрибутив, ядро |
| `uptime` | Время работы и среднюю нагрузку за 1, 5 и 15 минут |
| `free -h` | Столбец `available` для оценки доступной памяти |
| `df -hT` / `df -i` | Свободные блоки и inode |
| `lsblk -f` / `findmnt` | Диски, файловые системы и точки монтирования |
| `systemctl --failed` | Юниты, завершившиеся ошибкой |
| `sudo ss -lntup` | Локальные адреса, порты и процессы |
| `ip -br addr` / `ip route` | Адреса интерфейсов и маршруты |
| `timedatectl status` | Часовой пояс и состояние синхронизации времени |

## 2. Службы и журналы

```bash
systemctl status nginx.service --no-pager
```

```bash
sudo journalctl -u nginx.service -b -n 80 --no-pager
```

```bash
sudo journalctl -k -b -p warning --no-pager
```

`-b` выбирает текущую загрузку, `-k` сообщения ядра, `-p warning` предупреждения и более серьёзные записи. Для предыдущей загрузки используйте `-b -1`, если журнал сохранился.

| Действие | Команда | Результат |
|---|---|---|
| Посмотреть конфигурацию юнита | `systemctl cat nginx.service` | Показывает основной файл и дополнения |
| Проверить конфигурацию nginx | `sudo nginx -t` | Проверяет синтаксис и доступ к указанным файлам |
| Перечитать конфигурацию nginx | `sudo systemctl reload nginx.service` | Применяет настройки при поддержке reload |
| Перезапустить службу | `sudo systemctl restart nginx.service` | Может прервать текущие подключения |
| Включить автозапуск и запустить | `sudo systemctl enable --now nginx.service` | Выполняет оба действия |
| Перечитать файлы юнитов | `sudo systemctl daemon-reload` | Применяет правки юнитов к менеджеру systemd |

Локальные дополнения к юниту создавайте через `sudo systemctl edit nginx.service`. После изменения параметров запуска проверьте `systemctl cat`, перезапустите службу в подходящее окно и подтвердите доступность приложения.

## 3. SSH, учётные записи и доступ

Подключайтесь под отдельной учётной записью. Проверьте полномочия и членство в группах.

```bash
ssh admin@server.example.com
```

```bash
id
```

```bash
sudo -l
```

Создайте ключ на клиенте и установите публичную часть в `~/.ssh/authorized_keys` нужной учётной записи. Закрытый ключ храните на клиенте. При первой авторизации сверьте отпечаток хоста с доверенным источником. Для обычных файлов используйте `700` на `~/.ssh` и `600` на `authorized_keys`.

```bash
ssh-keygen -t ed25519
```

Перед правкой `/etc/ssh/sshd_config`, включённых файлов или правил firewall сохраните текущую SSH-сессию. Проверьте конфигурацию OpenSSH и узнайте имя юнита. В Debian/Ubuntu обычно используется `ssh.service`, в Arch — `sshd.service`. Некоторые установки принимают подключения через `ssh.socket`.

```bash
sudo sshd -t
```

```bash
systemctl list-unit-files 'ssh*'
```

После применения настроек проверьте вход во второй сессии. Для удалённых изменений правил firewall заранее убедитесь, что разрешён административный порт и доступна консоль провайдера. При правке sudoers используйте `sudo visudo`.

## 4. Обновления и резервные копии

- **Debian и Ubuntu.** Начните с `sudo apt update` и `apt list --upgradable`. Проверьте список перед `sudo apt upgrade`. См. [APT](Apt.md).
- **Arch Linux.** Проверьте новости дистрибутива и выполните полное обновление через `sudo pacman -Syu`. См. [pacman](Pacman.md).
- **До обслуживания.** Сохраните данные приложений, нужные файлы из `/etc`, список пакетов и параметры развёртывания. Для работающей СУБД используйте её средства резервного копирования.
- **После обслуживания.** Проверьте службы, журналы и пользовательский сценарий. Проверяйте восстановление копии в отдельном окружении. Храните копию отдельно от сервера и ограничивайте доступ к ней.

## 5. Частые симптомы

| Симптом | Что проверить |
|---|---|
| `Unit not found` | Имя юнита и установленный пакет через `systemctl list-unit-files` |
| `Connection refused` | Слушает ли процесс нужный адрес и порт через `ss` |
| Тайм-аут подключения | Маршрут, серверный firewall и правила сети провайдера |
| Служба завершилась после правки | Проверку конфигурации, `systemctl status` и журнал юнита |
| `No space left on device` | Заполненность блоков, inode и файловую систему назначения. См. [очистку Linux](Linux-Cleanup.md) |
