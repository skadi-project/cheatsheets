# Linux — основные команды

## 1. Что это и зачем

Эта шпаргалка помогает работать в терминале Linux с файлами, текстом, процессами, сетью, правами и службами. Команды ориентированы на Ubuntu/Debian и Arch Linux. Для управления пакетами используйте [APT](Apt.md) и [pacman](Pacman.md).

## 2. Установка

Базовые команды входят в дистрибутив. Проверить систему и оболочку можно так.

```bash
cat /etc/os-release
uname -a
printf '%s\n' "$SHELL"
```

В Windows используйте WSL или виртуальную машину Linux. В macOS часть команд доступна, но пути и службы отличаются.

## 3. Особенности и права

- `sudo` запускает одну команду с правами администратора. Перед изменением системы проверьте путь и параметры.
- `~` — домашний каталог, `.` — текущий, `..` — родительский каталог.
- Linux различает регистр. `/tmp/a` и `/tmp/A` — разные пути.
- Права разделяются на владельца `u`, группу `g` и остальных `o`.
- В WSL системные службы и сетевые адреса могут работать иначе, чем в полноценном Linux.

## 4. Быстрый старт

```bash
practice_dir=$(mktemp -d)
cd "$practice_dir" || exit 1
printf 'hello\n' > greeting.txt
cat greeting.txt
ls -la
rm -- greeting.txt
cd ..
rmdir -- "$practice_dir"
```

## 5. Справочник команд

В примерах пути заключены в кавычки, чтобы имена с пробелами обрабатывались целиком. Команды с `sudo` изменяют систему или чужие файлы.

### Навигация и файлы

#### `pwd` — текущий каталог

```bash
pwd
pwd -L  # логический путь с символическими ссылками
pwd -P  # физический путь без символических ссылок
```

Возможные ошибки — команда почти всегда завершается успешно. Если путь недоступен, проверьте права на родительские каталоги и состояние файловой системы.

#### `ls` — содержимое каталога

```bash
ls
ls -lah -- "/var/log"
ls -lt --time-style=long-iso .
ls -ld ./*/  # только каталоги
```

`-l` показывает подробности, `-a` скрытые файлы, `-h` размеры в удобном виде, `-t` сортировку по времени. `ls: cannot open directory` означает отсутствие права чтения каталога. `No such file` означает неверный путь.

#### `cd` — переход

```bash
cd /var/log
cd -- "$HOME/Documents"
cd -     # предыдущий каталог
cd       # домашний каталог
```

Ошибка `No such file or directory` означает неверный путь. `Permission denied` обычно означает отсутствие права `x` на один из каталогов пути.

#### `mkdir` — создание каталогов

```bash
mkdir "reports"
mkdir -p "project/src/tests"
mkdir -m 750 "private"
```

`-p` создаёт родителей, `-m` задаёт права. `File exists` можно получить без `-p`. `Permission denied` означает отсутствие права записи в родительский каталог. Не используйте `sudo`, пока не проверили владельца каталога.

#### `touch` — файл и время изменения

```bash
touch "notes.txt"
touch -a "notes.txt"            # только время доступа
touch -d '2026-01-01 12:00' "notes.txt"
```

`touch` не создаст файл в несуществующем каталоге. `Permission denied` означает отсутствие права записи. Если файл принадлежит другому пользователю, сначала проверьте `ls -l`.

#### `cp` — копирование

```bash
cp -- "source.txt" "copy.txt"
cp -a -- "project" "project.backup"  # сохранить атрибуты
cp -r -- "src" "backup/src"
cp -i -- "new.conf" "/etc/example.conf"  # спросить перед заменой
```

`-r` копирует каталоги, `-a` сохраняет атрибуты, `-i` спрашивает перед перезаписью. Ошибка `omitting directory` означает, что для каталога не указан `-r`. `No space left on device` означает нехватку места.

#### `mv` — перемещение и переименование

```bash
mv -- "old.txt" "new.txt"
mv -- "report.txt" "$HOME/Documents/"
mv -i -- "new.conf" "/etc/example.conf"
```

По умолчанию существующий файл может быть перезаписан. Используйте `-i` или `-n`. `Cross-device link` для некоторых операций между файловыми системами исправляется копированием с последующим удалением, если это безопасно.

#### `rm` — удаление

```bash
rm -- "obsolete.txt"
rm -i -- ./*.tmp
rm -r -- "build"
```

`rm -r` удаляет каталог рекурсивно, `rm -f` игнорирует отсутствующие файлы и отключает запросы подтверждения, а сочетание `rm -rf` может удалить большие объёмы без подтверждения. Перед удалением проверяйте `pwd`, `ls` и расширение шаблона. `Permission denied` может означать защищённый файл или отсутствие права записи в каталоге.

#### `ln -s` — символическая ссылка

```bash
ln -s -- "/opt/app/releases/42" "current"
ln -sfn -- "/opt/app/releases/43" "current"  # обновить ссылку на каталог
readlink -f -- "current"
```

Сломанная ссылка указывает на отсутствующий путь. `File exists` означает, что имя уже занято. `ln -sfn` с каталогами имеет нюансы на разных системах, поэтому перед заменой проверьте `ls -ld current`.

#### `file` — тип файла

```bash
file -- "archive.tar.gz"
file -b -- "image.bin"  # без имени файла
file --mime-type -- "report.pdf"
```

Если путь не найден, исправьте имя или рабочий каталог. Вывод `data` означает, что утилита не распознала формат, а не обязательно повреждение файла.

#### `stat` — метаданные

```bash
stat -- "notes.txt"
stat -c '%A %U:%G %s %n' -- "notes.txt"  # Linux
stat -c '%a' -- "script.sh"             # числовые права в Linux
```

Формат `-c` относится к GNU `stat`. В macOS синтаксис отличается. `No such file` означает неверный путь. Для доступа к метаданным каталога нужны права поиска по его родителям.

#### `find` — поиск по дереву

```bash
find . -type f -name '*.log'
find "$HOME" -type f -size +100M -print
find . -type f -name '*.tmp' -exec ls -l -- {} +
find . -type f -mtime -1 -user "$USER"
```

`-type f` — обычные файлы, `-type d` — каталоги, `-mtime` — возраст в днях. Пути и шаблоны заключайте в кавычки. `Permission denied` можно ограничить через `2>/dev/null`, но не скрывайте ошибки, если ищете проблему с правами. Не добавляйте `-delete`, пока не проверили результат без удаления.

#### `locate` — поиск по индексу

```bash
locate ssh_config
locate -i 'readme.md'
locate -b 'ash'
```

База может быть устаревшей. Обновление выполняется отдельной службой или командой `sudo updatedb`, если пакет установлен. `command not found` означает, что `plocate` или `mlocate` не установлен.

### Чтение и обработка текста

#### `cat`, `less`, `head`, `tail`

```bash
cat -- "config.txt"
cat -n -- "config.txt"
less -- "app.log"
less +G -- "app.log"  # начать с конца
head -n 20 -- "file.txt"
tail -n 50 -- "app.log"
tail -f -- "app.log"
```

`cat` удобен для небольших файлов, `less` завершайте клавишей `q`. `tail -f` остановите `Ctrl+C`. `No such file` исправляется проверкой пути. Ошибка кодировки обычно означает, что файл не в ожидаемой кодировке.

#### `grep` — поиск строк

```bash
grep -n 'ERROR' -- "app.log"
grep -RIn --exclude-dir=.git 'TODO' .
grep -E 'error|warning' -- "app.log"
grep -F 'literal[text]' -- "file.txt"
grep -RIl 'needle' .
```

`-n` показывает номера строк, `-R` рекурсивный поиск, `-i` игнорирует регистр, `-E` включает расширенные регулярные выражения, `-F` ищет буквальный текст. Код выхода `1` означает «совпадений нет», это не обязательно ошибка. `Permission denied` означает, что часть дерева недоступна.

#### `sort` и `uniq` — сортировка и подсчёт

```bash
sort -- "names.txt"
sort -n -- "numbers.txt"
sort -u -- "names.txt"
sort -- "names.txt" | uniq -c | sort -nr
```

`uniq` удаляет только соседние дубли, поэтому обычно сначала нужен `sort`. `sort -n` предназначен для чисел, а не для строк с единицами измерения. Ошибка чтения означает неверный путь или права.

#### `wc` — подсчёт

```bash
wc -- "file.txt"
wc -l -- "file.txt"
wc -w -c -- "file.txt"
grep -RIl 'TODO' . | wc -l
```

`-l` — строки, `-w` — слова, `-c` — байты, `-m` — символы. Для Unicode результат `-c` и `-m` может различаться. Пустой файл не является ошибкой и даст нулевые значения.

#### `cut` — извлечение полей

```bash
cut -d: -f1 -- /etc/passwd
cut -d, -f1,3 -- "data.csv"
cut -c1-10 -- "file.txt"
```

`-d` задаёт один разделитель, `-f` выбирает поля, `-c` символы. `cut` не разбирает CSV с разделителями внутри кавычек. Для сложного CSV используйте специализированный парсер. Ошибка `delimiter must be a single character` означает неверный `-d`.

#### `sed` — потоковая обработка

```bash
sed -n '1,20p' -- "file.txt"
sed '/^#/d' -- "config.txt"
sed 's/old/new/g' -- "input.txt" > "output.txt"
sed -i.bak 's/old/new/g' -- "config.txt"  # создать резервную копию
```

Без `-i` `sed` печатает результат и не меняет файл. `-i.bak` — GNU-синтаксис с резервной копией, в macOS формат отличается. Ошибка `unterminated 's' command` означает незакрытый шаблон или разделитель.

#### `awk` — поля и условия

```bash
awk '{print $1}' -- "file.txt"
awk -F: '{print $1, $7}' /etc/passwd
awk '$3 > 100 {print $1, $3}' -- "data.txt"
awk '{sum += $2} END {print sum}' -- "data.txt"
```

`$1`, `$2` — поля, `$0` — вся строка, `NF` — число полей, `NR` — номер строки. Неверный разделитель даёт пустые или смещённые поля. Пустой вывод может означать отсутствие совпадений, а не сбой.

#### `tee` — запись и передача потока

```bash
printf 'build started\n' | tee -- "run.log"
command 2>&1 | tee -a -- "run.log"
sudo tee /etc/example.conf > /dev/null <<'EOF'
option=value
EOF
```

`-a` дописывает, а не перезаписывает. Ошибка записи означает недоступный путь или отсутствие прав. `tee` обычно возвращает код ошибки записи, но для кода самой команды в конвейере может понадобиться `set -o pipefail` в Bash.

### Процессы и службы

#### `ps`, `top`, `pgrep`

```bash
ps
ps aux --sort=-%cpu | head
ps -o pid,ppid,stat,cmd -p 1234
top
top -b -n 1
pgrep -a nginx
pgrep -u "$USER" -f 'python.*worker'
```

`ps aux` показывает процессы всех пользователей. `top` завершайте `q` или `Ctrl+C`. Отсутствие вывода `pgrep` означает отсутствие совпадений. Для просмотра процессов другого пользователя могут потребоваться права.

#### `kill`, `killall`

```bash
kill 1234
kill -TERM 1234
kill -HUP 1234
kill -KILL 1234  # крайний вариант
killall -u "$USER" app
killall -i -TERM app
```

Сначала используйте `TERM`, затем проверьте процесс, и только потом `KILL`. `Operation not permitted` означает отсутствие права или попытку управлять чужим процессом. `No such process` означает, что PID уже завершился. `killall` по имени может затронуть несколько процессов.

#### `jobs`, `systemctl`, `journalctl`

```bash
sleep 100 &
jobs -l
jobs -p
fg %1
systemctl status ssh
sudo systemctl restart ssh
sudo systemctl enable --now ssh
journalctl -u ssh -b --no-pager
journalctl -u ssh --since '1 hour ago' -f
```

`jobs`, `fg` и фоновые задания относятся к текущей оболочке. `systemctl` требует systemd и имя существующей службы. `Unit not found` означает неверное имя или отсутствие службы. `journalctl` может показать `Permission denied` для чужих журналов, используйте `sudo` только при необходимости.

### Диск, сеть и архивы

#### `df`, `du`, `free`

```bash
df -hT
df -i
du -sh -- "$HOME/Downloads"
sudo du -xhd1 /var | sort -h
free -h
free -hw
```

`df` показывает свободное место файловой системы, `df -i` — свободные inode, `du` — фактический размер каталогов, `free` — память. `du` может выдавать `Permission denied`; не скрывайте это, если ищете причину нехватки места. Временные значения `free` не являются статистикой нагрузки приложения.

#### `ip`, `ss`, `ping`

```bash
ip addr show
ip route
ip route get 192.0.2.1
ip -br addr
ss -tulpn
ss -ltn 'sport = :22'
ping -c 4 1.1.1.1
ping -c 4 example.com
```

`ip addr` показывает адреса, `ip route` маршруты, `ss` слушающие сокеты. `ss -p` может требовать `sudo` для PID чужих процессов. `ping` может быть запрещён firewall и не доказывает доступность TCP-порта. `Name or service not known` указывает на проблему DNS.

#### `curl`, `ssh`

```bash
curl -I -- https://example.com
curl -fsS -- https://example.com/health
curl -o "page.html" -- https://example.com
ssh user@host
ssh -p 2222 -i "$HOME/.ssh/id_ed25519" user@host
ssh -o ConnectTimeout=5 user@host 'uname -a'
```

`-f` делает HTTP-ошибки ошибкой команды, `-sS` скрывает прогресс, но оставляет сообщения, `-I` запрашивает заголовки. Ошибка TLS требует проверки времени, сертификата и имени хоста, а не отключения проверки вслепую. `Permission denied (publickey)` у SSH означает проблему с ключом или серверной настройкой. `Connection refused` означает, что порт доступен, но служба не принимает соединение.

#### `tar`, `rsync`

```bash
tar -czf "backup.tar.gz" "project/"
tar -tzf "backup.tar.gz"
tar -xzf "backup.tar.gz" -C "restore/"
rsync -av -- "project/" "backup/"
rsync -av --delete --dry-run -- "project/" "backup/"
rsync -av -e 'ssh -p 2222' -- "project/" user@host:~/project/
```

У `tar -c` создание, `-x` распаковка, `-t` просмотр, `-z` gzip, `-f` имя архива. Перед распаковкой в текущий каталог проверяйте `tar -tzf`. `rsync` с завершающим `/` копирует содержимое каталога, без него — сам каталог. `--delete` удаляет в назначении отсутствующее в источнике, поэтому сначала используйте `--dry-run`. Ошибки SSH наследуются от `ssh`.

### Права и окружение

#### `id`, `whoami`

```bash
whoami
env whoami
id
id "$USER"
groups
```

Если `id user` сообщает `no such user`, проверьте имя и источник учётных записей. Список групп может обновиться только после нового входа в систему.

#### `chmod` — права файла

Проверка текущих прав:

```bash
ls -l -- "script.sh"
stat -c '%A %a %n' -- "script.sh"
```

У числового режима три цифры соответствуют владельцу, группе и остальным. В каждой цифре складываются права:

| Число | Право | Для файла | Для каталога |
|---:|---|---|---|
| `4` | `r` | читать содержимое | просматривать имена |
| `2` | `w` | изменять содержимое | создавать, удалять и переименовывать элементы при наличии `x` |
| `1` | `x` | запускать как программу | входить и обращаться к элементам по имени |
| `0` | `---` | нет права | нет права |

Примеры сочетаний `4 + 2 + 1`:

| Режим | Расшифровка |
|---:|---|
| `700` | владелец `rwx`, группа `---`, остальные `---` |
| `755` | владелец `rwx`, группа `r-x`, остальные `r-x` |
| `644` | владелец `rw-`, группа `r--`, остальные `r--` |
| `600` | владелец `rw-`, группа и остальные без доступа |
| `640` | владелец `rw-`, группа `r--`, остальные без доступа |
| `664` | владелец и группа `rw-`, остальные `r--` |
| `750` | владелец `rwx`, группа `r-x`, остальные без доступа |

Применение числовых и символьных прав:

```bash
chmod 644 -- "config.ini"       # обычный нечувствительный файл
chmod 600 -- "$HOME/.ssh/id_ed25519"  # приватный ключ
chmod 755 -- "script.sh"        # владелец меняет и запускает, остальные запускают
chmod 750 -- "private-dir"      # группа может войти и читать каталог
chmod u+x -- "script.sh"        # добавить запуск владельцу
chmod g-w,o-r -- "shared.txt"   # убрать запись у группы и чтение у остальных
chmod a=rx -- "public-dir"      # задать чтение и вход всем
chmod -R u+rwX,go+rX -- "project" # X добавляет запуск каталогам и уже исполняемым файлам
```

`x` для каталога означает право прохода, поэтому `r` без `x` обычно не даёт нормально открыть элементы. Для приватного каталога часто используют `700`, для обычного файла `644`, для запускаемого скрипта `755` или более ограниченный `750`.

Сочетания внутри одной цифры: `0` = `---`, `1` = `--x`, `2` = `-w-`, `3` = `-wx`, `4` = `r--`, `5` = `r-x`, `6` = `rw-`, `7` = `rwx`. Например, `754` означает `rwxr-xr--`.

Специальные биты:

```bash
chmod 2750 -- "shared-dir" # setgid, новые элементы наследуют группу каталога
chmod 1777 -- "/tmp/example" # sticky bit, удалять элементы могут их владельцы, владелец каталога или привилегированный процесс
```

Восьмеричная форма может содержать четыре цифры. Первая задаёт специальные биты: `4` — setuid, `2` — setgid, `1` — sticky. Setuid у исполняемого бинарника может менять эффективный UID процесса на UID владельца файла. Не назначайте этот бит без необходимости. `chmod: Operation not permitted` означает, что текущий пользователь не владеет файлом, не имеет необходимых полномочий или операция запрещена файловой системой. `chmod: cannot access` означает неверный путь. `chmod -R` меняет права всего дерева, поэтому сначала проверьте `find` и применяйте его осторожно.

#### `chown` — владелец и группа

```bash
sudo chown user -- "file"
sudo chown user:group -- "file"
sudo chown -R user:group -- "project"
sudo chown --reference="template" -- "copy"
```

Ошибка `invalid user` или `invalid group` означает, что имя отсутствует. `Operation not permitted` означает недостаточные права. Перед `-R` проверьте корень пути: ошибка в переменной может изменить владельца большого дерева.

#### `umask` — права новых файлов

```bash
umask
umask -S
umask 022
(umask 077; touch -- "private.txt")
```

`umask` убирает права из базовых прав создания. При `022` обычный файл обычно получает `644`, каталог `755`. При `077` файл обычно получает `600`, каталог `700`. Итог также зависит от программы. Если новый файл получил более строгие права, проверьте режим, который запрашивает программа. Если существующий файл не изменился, используйте `chmod`.

#### `env`, `export`, `command -v`

```bash
env | sort
env APP_ENV=prod printenv APP_ENV
export APP_ENV=dev
export EDITOR=vi
command -v python3
command -V ls
```

Переменная без `export` видна только текущей оболочке. `command -v` с пустым выводом означает, что команда не найдена в `PATH`. `env` может раскрыть секреты, поэтому не публикуйте его вывод.

#### `man`, `history`

```bash
man chmod
man 5 passwd
man -k 'archive'
history 20
history | grep 'ssh'
```

`man` не найден означает отсутствие пакета manpages или минимальную установку системы. `No manual entry` означает отсутствие страницы для команды. Если `history` пуст, проверьте, включена ли история и запущен ли интерактивный Bash. История может содержать токены и пароли, переданные прямо в командной строке. Не публикуйте файл истории.

## 6. Конфигурация

Настройки пользователя обычно находятся в `~/.profile`, `~/.bashrc`, `~/.zshrc` или `~/.config/fish/config.fish`. Конфигурация systemd-служб — в `/etc/systemd/system/` и каталогах дистрибутива.

```bash
printf 'export EDITOR=vi\n' >> "$HOME/.profile"
. "$HOME/.profile"
```

Проверяйте команды и пути перед добавлением строк в shell-профиль. Ошибка в нём может изменить запуск новых терминалов.

## 7. Полезные приёмы

- Используйте Tab для автодополнения и `Ctrl+R` для поиска в истории.
- `command > file` перезаписывает файл, `command >> file` дописывает, `command 2> errors.log` сохраняет stderr, `command | less` листает вывод.
- `command1 && command2` запускает вторую команду только после успеха первой, `command1 || command2` — после ошибки.
- Для имён с пробелами используйте кавычки и `find ... -print0 | xargs -0`.
- Перед опасными `rm`, `chmod -R`, `chown -R`, `rsync --delete` и `tar -x` сначала выполните безопасный просмотр результата.
- В Bash для контроля ошибок конвейера используйте `set -o pipefail`.

## 8. Частые ошибки

| Ошибка | Причина | Решение |
|---|---|---|
| `Permission denied` | Нет права на файл, каталог или запуск | Проверьте `ls -l`, `namei -l путь`, владельца и группу |
| `No such file or directory` | Неверный путь, регистр или отсутствующая команда | Проверьте `pwd`, `command -v` и кавычки |
| `command not found` | Команда не установлена или не входит в `PATH` | Выполните `command -v`, установите пакет или исправьте `PATH` |
| `Address already in use` | Порт занят | Проверьте `ss -tulpn` и остановите нужный процесс |
| `Read-only file system` | Файловая система смонтирована только для чтения | Проверьте `findmnt`, ошибки диска и параметры монтирования |
| `No space left on device` | Закончились блоки или inode | Проверьте `df -h`, `df -i`, `du -xhd1` |
| `Unit not found` | Неверное имя systemd-службы | Используйте `systemctl list-unit-files` |
| `Could not resolve host` | Ошибка DNS или сети | Проверьте `ip route`, DNS и доступность адреса |
| `Operation not permitted` | Недостаточно прав или операция запрещена владельцем ФС | Проверьте владельца, mount-параметры и необходимость `sudo` |
